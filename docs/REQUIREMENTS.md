# KadaiNotify 要件定義書

- 版: v1.0(2026-11-26 合意。実装中に分かった点を反映)
- 作成日: 2026-11-26
- 対象: 自分専用の iOS アプリ(配布しない)

> この文書の読み方: 「F-」で始まるのが機能要件(アプリが何をできるか)、「N-」が非機能要件(速さ・安全さ・作りの決まりなど)。
> 各要件の「受け入れ条件」は「これができたら完成とみなす」チェック項目。
> 【要確認】が付いている所は、ユーザーとまだ合意していない提案。

---

## 1. 背景と目的

### 1.1 困りごと
- 後期になってやることが増え、大学の提出物(課題・レポート)を落としそうになっている。
- 学生ポータルには TODO として課題が載るが、**プッシュ通知が来ない**ので気づけない。
- いまは Mac の Claude in Chrome でポータルから提出物を探し、Google カレンダーの ToDo(Google Tasks)に入れている。ただし Google Tasks は
  - iPhone の標準カレンダーに同期されない(アプリから読めない)
  - 締め切りの「時刻」を持てない(日付だけ)
  ため、締め切り通知の土台としては弱い。

### 1.2 目的
1. 提出物の締め切りを **iPhone の通知で確実に知らせる**。
2. 終わるまで **しつこく思い出させる**(完了チェックを付けるまで毎晩通知)。
3. Mac の Claude で見つけた提出物を、**手打ちせずに**アプリへ入れられる。

### 1.3 役割分担(ユーザーの理想)
| 置き場所 | 入れるもの |
|---|---|
| **このアプリ** | 提出物・課題(タスク)だけ |
| Google カレンダー | それ以外の予定(授業、バイト、約束など) |

→ 提出物を Google カレンダーに入れる運用はやめ、アプリに一本化する。

## 2. 利用者と利用環境

| 項目 | 内容 |
|---|---|
| 利用者 | 本人 1 人のみ |
| 端末 | iPhone(**iOS 18 以上**) |
| 開発・ビルド | 本人の MacBook + Xcode(DGX にはソースの最新版を置き、GitHub で同期) |
| 署名 | **無料の Apple ID(Personal Team)**。7 日ごとに Mac から入れ直しが必要 |
| 提出物の発見 | Mac の Chrome + Claude in Chrome で学生ポータルを見る |
| ネットワーク | アプリ自体は**ネット接続なし**で動く(サーバーを持たない) |

## 3. 用語

| 用語 | 意味 |
|---|---|
| 課題 | 提出物 1 件。科目・課題名・締め切り日時・メモを持つ |
| 科目 | 課題の分類。色と通知設定を持てる |
| 個別通知 | 課題 1 件について「3 日前の 21:00」などに鳴る通知 |
| 毎晩のまとめ通知 | 毎晩 1 回、未完了の課題をまとめて知らせる通知 |
| 取り込みテキスト | Claude が出力し、コピー&貼り付けでアプリへ一括登録するための決まった形式の文字列(7 章) |
| ローカル通知 | サーバーを使わず、iPhone の中だけで予約して鳴らす通知(`UNUserNotificationCenter`) |

## 4. スコープ

### 4.1 最初の版(v1)に入れるもの
| ID | 機能 |
|---|---|
| F-01 | 課題の登録・編集・削除 |
| F-02 | 課題一覧(締め切りが近い順・期限切れを目立たせる) |
| F-03 | 完了チェック |
| F-04 | 個別通知(全体 → 科目 → 課題 の順で上書きできる) |
| F-05 | 毎晩のまとめ通知(未完了がある限り毎晩) |
| F-06 | 科目の管理と色分け |
| F-07 | 毎週の繰り返し課題 |
| F-08 | 取り込みテキストの貼り付けによる一括登録 |
| F-09 | アプリアイコンの数字バッジ |
| F-10 | ホーム画面ウィジェット(表示のみ) |
| F-11 | 設定画面 |
| F-12 | 署名の期限切れ前のお知らせ(無料 Apple ID 用) |

### 4.2 次の版以降(v2〜)
- スクショを渡して文字認識で取り込む(iPhone 内の文字認識 Vision を使用)
- 通知を長押しして「完了」「1 時間後にもう一度」
- ウィジェットから直接完了チェック(インタラクティブウィジェット)
- 取り込みファイル(AirDrop で送る `.json`)
- バックグラウンドで通知予約を自動更新(アプリを開かなくても 2 週間以上鳴り続ける)
- データの書き出し/読み込み(バックアップ)
- 時間割の登録と、科目選択の補助

### 4.3 やらないこと
- 学生ポータルへの自動ログイン・自動読み取り(パスワードを扱うことになり、大学の規則上も危ないため)
- サーバー・Web Push・アカウント機能
- Google カレンダー / Google Tasks との連携
- 他人との共有、Android 対応、App Store での公開

## 5. 機能要件

### F-01 課題の登録・編集・削除
- 項目:

  | 項目 | 必須 | 備考 |
  |---|---|---|
  | 科目 | ○ | 既存の科目から選ぶか、新しく入力(新しい名前なら科目を自動作成) |
  | 課題名 | ○ | 例: 「第 8 回レポート」 |
  | 締め切り日時 | ○ | 日付+時刻。時刻が不明なときの初期値は **8:50**(1 限開始前) |
  | メモ | − | 提出方法、ページ数など自由記述 |
  | 通知設定 | − | 未指定なら科目 → 全体の設定を使う(F-04) |
- 編集画面から削除できる(確認ダイアログあり)。一覧の左スワイプでも削除できる。

受け入れ条件
- [ ] 課題名が空のときは保存ボタンが押せない
- [ ] 保存・編集・削除のたびに通知の予約が作り直される
- [ ] アプリを終了して開き直してもデータが残っている

### F-02 課題一覧
- 未完了の課題を次のグループに分けて、それぞれ締め切りが近い順に並べる:
  1. **期限切れ**(赤)
  2. **今日**(オレンジ)
  3. **明日**
  4. **それ以降**
  5. 完了済み(初期状態は折りたたみ。最近完了した順)
- 各行の表示: 科目名(科目の色の印)、課題名、締め切り「12/3(木) 17:00」、残り時間「あと 2 日」「あと 3 時間」「5 時間超過」。
- 表示は 1 分ごとに自動で更新(開いたまま締め切りを過ぎたら期限切れへ移る)。
- 課題が 0 件のときは「提出物はありません」と表示し、追加ボタンへ誘導する。

受け入れ条件
- [ ] 締め切りを過ぎた未完了の課題が一番上に赤で出る
- [ ] 行をタップすると編集画面が開く

### F-03 完了チェック
- 行の左の丸をタップで完了/未完了を切り替え。右スワイプでも完了。
- 完了すると、その課題の個別通知は取り消し、まとめ通知からも外れる。
- 完了済みを未完了に戻すと通知も戻る。

受け入れ条件
- [ ] 完了にした課題について、それ以降の通知が一切来ない
- [ ] 通知センターに残っている、その課題の通知も消える

### F-04 個別通知
- 通知のタイミングは「ルール」のリストで表す。ルールは 2 種類:
  - **N 日前の HH:MM**(例: 3 日前の 21:00)
  - **N 時間前**(例: 3 時間前)
- 適用の優先順位: **課題ごとの設定 > 科目ごとの設定 > 全体の設定**。上位で「指定なし」なら下位を使う。
- 全体の初期値: **3 日前の 21:00、1 日前の 21:00**。
- 通知の文面(例):
  - タイトル: 「【情報システム】第 8 回レポート」
  - 本文: 「締め切り 12/3(木) 17:00(あと 2 日)」
- 鳴る時刻がすでに過ぎているルールは予約しない(例: 締め切りの 2 日前に登録したら「3 日前」は鳴らない)。
- 同じ時刻に「毎晩のまとめ通知」と重なった個別通知は、まとめ通知の中に含めて 1 通にする(通知が二重に来ないように)。

受け入れ条件
- [ ] 全体設定だけの状態で、木曜 17:00 締め切りの課題を登録すると、月曜 21:00 と水曜 21:00 に知らせが来る
- [ ] 科目に「7 日前の 21:00」を追加すると、その科目の課題だけ 7 日前にも鳴る
- [ ] 課題に個別設定を入れると、科目・全体の設定より優先される

### F-05 毎晩のまとめ通知
- **未完了の課題が 1 件でもある限り、毎晩 21:00(変更可)に 1 通**届く。期限切れの課題も、完了か削除するまで含め続ける。
- 文面(例):
  - タイトル: 「未完了の提出物 3 件(期限切れ 1)」
  - 本文: 期限切れ → 今夜知らせるべきもの(🔔、個別通知をまとめたもの)→ その他 の順に最大 4 件。5 件目以降は「ほか N 件」
    ```
    ⚠️ 期限切れ 情報システム 第7回レポート
    🔔 明日 17:00 論理回路 演習課題5
    ・ 12/5(土) 8:50 PD入門 振り返りシート
    ```
- 設定でオフにできる。

受け入れ条件
- [ ] 未完了が 0 件の夜は鳴らない
- [ ] 夜までに全部完了すると、その夜は鳴らない

### F-06 科目の管理と色分け
- 科目は名前・色(8 色から選ぶ)・通知設定(F-04、任意)を持つ。
- 課題の登録時や取り込み時に、知らない科目名が出てきたら自動で作る(色は自動で割り当て、あとで変更可)。
- 科目を削除するときは、その科目の課題が残っていれば削除できない(先に課題を移すか消す)。

受け入れ条件
- [ ] 一覧で科目ごとに色の印が付く
- [ ] 科目の色を変えると、一覧・ウィジェットにすぐ反映される

### F-07 毎週の繰り返し課題
- 「毎週 ○曜日 HH:MM 締め切り」のひな形を登録できる。項目: 科目、課題名(「第 {n} 回 小テスト」のように回数を入れられる)、曜日、時刻、開始日、終了日(学期末)。
- アプリは**締め切りが今から 14 日以内の回**をすべて課題として作る(= おおむね 2 週分先まで)。
  - アプリを開くたびに確認し、14 日以内に入った回を追加する。
  - 作った回は普通の課題と同じ扱い(個別に編集・完了・削除できる)。削除した回は作り直さない。
- 終了日を過ぎたら作らない。ひな形はいつでも停止・削除できる。

受け入れ条件
- [ ] 毎週木曜 17:00 のひな形を作ると、今後 14 日以内の木曜 17:00 の課題(2 件)が一覧に出る
- [ ] 1 週間たってアプリを開くと、新しく 14 日以内に入った回が 1 件増える
- [ ] 作られた回を削除しても、同じ回が作り直されない

### F-08 取り込みテキストの貼り付けによる一括登録
- 一覧画面の「取り込み」から、クリップボードの文字を貼り付ける。
- 7 章の形式を読み取り、**登録前に確認画面**を出す(1 件ずつチェックを外せる。科目・課題名・締め切りはその場で直せる)。
- 読み取れなかった行は理由付きで表示し、登録はしない。
- 重複判定: 「科目+課題名+締め切り日」が同じ課題がすでにあれば「登録済み」として既定でチェックを外す。締め切り時刻だけ違う場合は「更新」として扱える。
- Mac でコピー → iPhone で貼り付けは、Apple の「ユニバーサルクリップボード」で行う(同じ Apple ID・Bluetooth と Wi-Fi オン・Handoff オン)。

受け入れ条件
- [ ] 7.3 の例をそのまま貼ると 3 件が確認画面に出て、登録できる
- [ ] 同じテキストをもう一度貼ると、3 件とも「登録済み」になる
- [ ] 時刻のない行は 8:50 として読み込まれる

### F-09 アプリアイコンのバッジ
- アイコンの赤丸の数字 = **未完了の課題の全件数**(期限切れも含む)。
- アプリを開いたとき・データを変えたときに更新。
- 設定でオフにできる。

受け入れ条件
- [ ] 期限切れ 1 件・今日締め切り 1 件・来週 1 件のとき、バッジは 3
- [ ] 1 件完了にするとバッジは 2 になる

### F-10 ホーム画面ウィジェット(表示のみ)
- 小サイズ: 次の締め切り 1 件(科目・課題名・残り時間)と未完了件数。
- 中サイズ: 締め切りが近い順に 3 件。
- 期限切れがあれば赤で先頭に出す。タップするとアプリが開く。
- 表示はおおむね 15 分ごと+アプリでデータを変えたときに更新(iOS の都合で正確な間隔は保証できない)。

受け入れ条件
- [ ] ホーム画面に小・中のウィジェットを置ける
- [ ] アプリで課題を完了にしてホーム画面に戻ると、ウィジェットから消えている

### F-11 設定画面
- 全体の通知ルール(F-04)の追加・削除・変更
- 毎晩のまとめ通知: オン/オフ、時刻
- バッジ: オン/オフ
- 時刻不明のときの初期時刻(初期値 8:50)
- 通知の許可状態の表示と、許可されていないときに iPhone の設定を開くボタン
- 「テスト通知(5 秒後)」ボタン
- 予約中の通知の件数(上限 64 件に対する使用状況)
- 取り込みテキスト用の「Claude への頼み方」をコピーするボタン(7.4)
- アプリの署名の期限(F-12)の表示

### F-12 署名の期限切れ前のお知らせ
- 無料 Apple ID で入れたアプリは、入れてから 7 日で開けなくなる。期限はアプリ内のファイル(`embedded.mobileprovision`)に書かれているので、アプリがそれを読み取る。
- **期限の 1 日前の 21:00** に「明日アプリの期限が切れます。Mac で入れ直してください」と通知する(まとめ通知と重なれば 1 通にまとめる)。
- 一覧画面の上部にも、期限まで 2 日を切ったら注意を出す。
- 期限が読み取れないとき(シミュレーターなど)は何もしない。

受け入れ条件
- [ ] Mac から入れた直後、設定画面に「署名の期限: 12/3(木) 14:20」のように表示される
- [ ] 期限の前日 21:00 に入れ直しのお知らせが届く

## 6. 非機能要件

| ID | 要件 |
|---|---|
| N-01 | データは iPhone の中だけに保存する(SwiftData)。ウィジェットと共有するため App Group の保存場所を使う |
| N-02 | 通信をしない。外部サービスのアカウントやパスワードを持たない |
| N-03 | iOS 18 以上。iPhone 縦画面を主とする(iPad は動けばよい) |
| N-04 | ダークモードで文字が読めること |
| N-05 | 画面の文言は日本語 |
| N-06 | 起動から一覧表示まで 1 秒以内(課題 200 件程度まで) |
| N-07 | 日時は日本時間(端末のタイムゾーン)で扱う |
| N-08 | 締め切り日時の計算など、画面に依存しない処理はテストを書く |
| N-09 | ソースは GitHub(kotakota914)で公開できる状態にする。公開前に個人情報スキャンを行う。実在の課題データやスクショはリポジトリに入れない |
| N-10 | 追加のライブラリを使わない(Apple 標準の SwiftUI / SwiftData / UserNotifications / WidgetKit のみ) |

## 7. 取り込みテキストの形式

### 7.1 形式
```
#kadai v1
科目 | 課題名 | 締め切り | メモ
```
- 1 行目は必ず `#kadai v1`(取り込み対象の目印)。
- 2 行目以降、1 行 = 1 課題。区切りは `|`(前後の空白は無視)。
- 締め切りの書き方: `2026-12-03 17:00` または `2026-12-03`(時刻なし → 設定の初期時刻 = 8:50)。
- メモは省略可。メモの中に `|` は使わない。
- 空行と `#` で始まる行(1 行目以外)は無視。

### 7.2 読み取りエラーにするもの
- 列が 3 つ未満、科目か課題名が空、日付が読めない。

### 7.3 例
```
#kadai v1
情報システム | 第8回レポート | 2026-12-03 17:00 | A4 2枚、Moodleに提出
論理回路 | 演習課題5 | 2026-12-04 23:59 |
PD入門 | 振り返りシート | 2026-12-05 | 時刻不明
```

### 7.4 Claude in Chrome への頼み方(テンプレート)
```
学生ポータルの TODO / 課題一覧から、まだ締め切りが来ていない提出物を全部探して、
次の形式だけを出力してください(説明文は不要)。

#kadai v1
科目 | 課題名 | 締め切り(YYYY-MM-DD HH:MM、時刻がわからなければ YYYY-MM-DD) | メモ

- 1 行に 1 件
- メモには提出方法など分かることを短く。なければ空欄
- 「|」は区切り以外に使わない
```

## 8. 通知の設計

### 8.1 予約数の上限
iOS は 1 つのアプリが予約できるローカル通知を **64 件まで**に制限している。そこで:
- 毎晩のまとめ通知: これから **14 晩分**を予約(14 件)
- 個別通知: 鳴る時刻が近い順に **最大 49 件**
- 署名期限のお知らせ: 1 件
- 合計 64 件以内に収める

### 8.2 予約し直すタイミング
- アプリを開いたとき、課題・科目・設定を変えたとき、取り込んだとき。
- 予約し直すときは「全部消して作り直す」方式(作りが単純で、ずれが出ない)。

### 8.3 既知の制約(v1)
- アプリを **14 日間開かないと**、毎晩のまとめ通知が止まる。14 晩目の通知には「アプリを開いて通知を更新してください」と入れる。(v2 のバックグラウンド更新で改善)
- 個別通知が 49 件を超える場合、遠い先のものは次にアプリを開くまで予約されない。

## 9. データ設計(概要)

| データ | 主な項目 |
|---|---|
| 課題 (Assignment) | id、科目、課題名、締め切り日時、メモ、完了フラグ、完了日時、個別通知ルール(任意)、作成元(手入力/取り込み/繰り返し)、繰り返しひな形への参照、作成日時 |
| 科目 (Subject) | id、名前(重複不可)、色、通知ルール(任意)、作成日時 |
| 繰り返しひな形 (RecurringTemplate) | id、科目、課題名のひな形、曜日、時刻、開始日、終了日、有効フラグ、次の回数 |
| 通知ルール (ReminderRule) | 種類(N 日前の HH:MM / N 時間前)、N、時、分 |
| 全体設定 | 全体の通知ルール、まとめ通知のオン/オフと時刻、バッジのオン/オフ、時刻不明時の初期時刻 |

## 10. 制約とリスク

| リスク | 影響 | 対策 |
|---|---|---|
| 無料 Apple ID は 7 日で期限切れ。期限切れ中はアプリが開けない | 通知の予約が更新されない。予約済みの通知が鳴り続けるかは未確認 | F-12 で前日に知らせる。README に入れ直し手順を書く。入れ直してもデータは消えない(アプリを削除しない限り) |
| 無料 Apple ID は 7 日間に作れる App ID が 10 個まで | ウィジェットで 2 個使う | 通常の開発では問題なし |
